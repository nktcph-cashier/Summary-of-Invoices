# ระบบใบสรุปการนำส่งเงิน — Login 6 USER

หน้าเว็บใช้ USER001 ถึง USER006 และ Password ไม่ต้องกรอกอีเมลจริง ระบบใช้ Firebase Email/Password ภายในผ่าน alias เท่านั้น ไม่มีรหัสผ่านฝังใน HTML และไม่มีหน้าสมัครสมาชิก

## ตั้งค่าก่อนใช้งานจริง
1. สำรองข้อมูลและ Rules เดิมใน Firebase project `nktcph-cashier-7a9d6`.
2. Authentication > Sign-in method: เปิด Email/Password และปิด Anonymous เมื่อพร้อมย้ายระบบเดิม.
3. Authentication > Users > Add user: สร้าง `user001@login.example.invalid` ถึง `user006@login.example.invalid` รวม 6 บัญชี พร้อมกำหนดรหัสผ่านที่รัดกุมและแตกต่างกันเอง ไม่ใช่อีเมลจริงและไม่สามารถรับจดหมายรีเซ็ตรหัสผ่านได้ ผู้ดูแลเป็นผู้จัดการรหัสผ่าน.
4. คัดลอก UID ของแต่ละบัญชี ไปสร้างใน Realtime Database > Data ที่ `allowed_users/<UID>` โดยกำหนดค่า boolean `true` (ไม่ใช่ข้อความ) จำนวน 6 รายการ.
5. ตรวจสอบและผสาน `database.rules.example.json` กับ Rules เดิมก่อน Publish โดยต้องไม่เหลือกฎ parent ที่อนุญาตให้บุคคลอื่นเข้าถึงข้อมูล ห้ามเปิดเขียน allowed_users ให้ client. ตัวอย่างครอบคลุม path ที่พบใน HTML เท่านั้น ไม่ควรทับ Rules เดิมโดยไม่ตรวจสอบ.
6. นำ index.html ไปแทนไฟล์เดิมบนโฮสต์. ทดสอบบัญชีทั้งหก เข้าผิดรหัส บัญชีที่ไม่ได้ allowlist การบันทึก พิมพ์ และออกจากระบบบน staging ก่อนใช้เงินจริง.

ทุกบัญชีใช้ข้อมูลกลางและสิทธิ์เท่ากันตามโครงสร้างเดิม. ไม่มีการย้ายหรือลบข้อมูล Firebase. ยังไม่ได้สร้างบัญชีหรือเผยแพร่ Rules จริง เนื่องจากไม่มีสิทธิ์เข้าถึง console. ไม่ควรเปิดใช้งานจริงจนกว่าจะตั้งค่าและทดสอบครบ. รหัสผ่านให้ผู้ดูแลกำหนดใน Firebase เท่านั้น.
